# GeneHub Frontend

## Project Overview
React frontend for GeneHub - a genetic/semen inventory management system for cattle breeding operations.

## Tech Stack
- React 18 with Vite
- Supabase (PostgreSQL + Auth)
- TanStack React Query for data fetching/caching
- React Router for navigation

## Architecture Decisions

### React Query Implementation (Completed)
All data fetching and mutations now use React Query (`@tanstack/react-query`) for:
- Automatic caching and deduplication
- Background refetching
- Stale-while-revalidate pattern
- Consistent mutation handling with `useMutation`

**Hooks using React Query for reads:**
| Hook | Query Keys |
|------|------------|
| `useSireList` | `['sires', {...params}]`, `['customers']` |
| `useInventoryList` (Genetic) | `['geneticInventory', {...params}]` |
| `useActivityLogList` | `['activityLog', {...params}]` |
| `useTankList` | `['tanks']`, `['canisters', tankId]`, `['canisterInventory', canisterId]` |
| `useCustomerList` | `['customers']`, `['customersWithInventory']` |
| `useInventoryDependencies` | `['customers']`, `['tanks']`, `['canisters', tankId]` |
| `useCategoryList` (Medical) | `['medicalCategories']` |
| `useInventoryList` (Medical) | `['medicalInventory']` |
| `useUsageLog` | `['usageHistory', itemId]` |
| `useTankDetails` | `['nitrogenFillHistory', tankId]`, `['nitrogenConsumptionStats', tankId]` |
| `useUserSettings` | `['userSettings', userId]` |

**QueryClient configuration** (in `main.jsx`):
```javascript
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5, // 5 minutes
      gcTime: 1000 * 60 * 30, // 30 minutes
      retry: 1,
      refetchOnWindowFocus: false,
    },
  },
});
```

### Mutation Pattern (Completed)
All create/update/delete operations use `useMutation` or the custom `useCRUDMutation` helper:

**Pattern for mutations:**
```javascript
const createMutation = useMutation({
  mutationFn: (data) => createSire(data, userId),
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ['sires'] });
    queryClient.invalidateQueries({ queryKey: ['sireCount'] }); // Dashboard counts
  },
});
```

**`useCRUDMutation` helper** - Wraps create/update/delete with:
- Automatic cache invalidation for specified query keys
- Minimum delay for UX (prevents flash of loading state)
- Consistent error handling

**Forms using mutations:**
| Hook | Mutation Pattern | Dashboard Invalidation |
|------|------------------|------------------------|
| `useSireForm` | `useCRUDMutation` | `sireCount` |
| `useCustomerForm` | `useCRUDMutation` | `customerCount` |
| `useInventoryForm` (Genetic) | `useCRUDMutation` | `geneticInventoryCounts` |
| `useInventoryForm` (Medical) | `useCRUDMutation` | `medicalInventoryStats` |
| `useCategoryForm` | `useCRUDMutation` | - |
| `useTankForm` | `useCRUDMutation` | - |
| `useCanisterForm` | `useCRUDMutation` | - |
| `useFillForm` | `useCRUDMutation` | - |
| `useUsageLog` | `useSimpleMutation` | `medicalInventoryStats` |

| `useInventoryList` (Medical) | `useMutation` (inline edit) | `medicalInventoryStats` |

### Dynamic Query Pattern with `useQueries`
For loading data based on dynamic IDs (e.g., canisters per expanded tank):

```javascript
const canisterQueries = useQueries({
  queries: expandedTankIds.map(tankId => ({
    queryKey: QUERY_KEYS.canisters(tankId),
    queryFn: async () => {
      const { data, error } = await fetchCanistersByTank(tankId);
      if (error) throw error;
      return data || [];
    },
    staleTime: 30000,
  })),
});

const canisters = useMemo(() => {
  const result = {};
  expandedTankIds.forEach((tankId, index) => {
    const query = canisterQueries[index];
    if (query?.data) {
      result[tankId] = query.data;
    }
  });
  return result;
}, [canisterQueries, expandedTankIds]);
```

### Server-Side Pagination (Partial)
Sires and Genetic Inventory use server-side pagination with:
- `fetchSiresPaginated()` - ILIKE search on name, breed, registration_number
- `fetchGeneticInventoryPaginated()` - Uses RPC function `search_genetic_inventory` for searching across joined tables
- Debounced search (300ms) via `useDebounce` hook

### Client-Side Pagination
Tanks, Customers, and Medical Inventory load all data then paginate client-side using `usePagination` hook.

### Async Sire Dropdown
`AsyncSearchableSelect` component fetches sires on-demand as user types, avoiding loading all sires upfront.

## Potential Improvements (Refactoring Opportunities)

### High Priority

**1. Form Hook Factory**
All 8 form hooks (`useSireForm`, `useCustomerForm`, `useInventoryForm`, `useCategoryForm`, `useTankForm`, `useCanisterForm`, `useFillForm`) repeat ~80% identical code:
- Same pattern: `useModalState` + `useConfirmModal` + `useCRUDMutation` + `useFormState` + `useFormValidation`
- Same return structure and handlers
- Could consolidate into a generic factory that takes config objects

**2. Standardize Mutation Approach**
Currently mixed:
- 5 forms use `useCRUDMutation` (sires, customers, inventories, categories)
- 3 forms use direct `useMutation` (tanks, canisters, fills)
- Migrate tank/canister/fill forms to `useCRUDMutation` for consistency

**3. Use `usePagination` Hook**
`usePagination` exists but `useSireList` and `useInventoryList` reimplement pagination locally (`goToPage`, `goToNextPage`, `goToPrevPage`). Should use the shared hook.

### Medium Priority

**4. `useCanisterForm` Inconsistency**
Creates custom `confirmDeleteCanisterState` instead of using `useConfirmModal` like all other forms.

**5. Centralized Data Sanitization**
Each form has its own string-to-null, trim, type conversion logic. Create shared utilities:
- `sanitizeString(val)` - trim and convert empty to null
- `toNumberOrNull(val)` - parse number or return null
- `sanitizeFormData(data, schema)` - apply rules based on field types

**6. Remove or Clarify `useAsyncOperation`**
Both `useAsyncOperation` and `useCRUDMutation` exist with overlapping purposes. Either remove `useAsyncOperation` if unused, or document when to use each.

### Low Priority

**7. Naming Consistency**
- Editing state: `editingSire` vs `editingCustomer` vs `editingItem` vs `editingInventory`
- List returns: `sires`/`rawSires` vs `customers` (no raw version)
- Standardize naming conventions across hooks

**8. Unified List Hook Pattern**
Create a `useListHook` factory with configurable:
- Server-side vs client-side filtering
- Standard refresh/search/filter patterns
- Consistent return structure
